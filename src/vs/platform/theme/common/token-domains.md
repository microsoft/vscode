# Choosing a token domain

Token-domain navigation summaries. Each domain retains its reference to the authoritative source and section; these summaries do not register new tokens or replace the source guidance.

## Spacing

Use the shared ramp for padding, margins, gaps, and spacers—not arbitrary structural dimensions.

## Typography

Choose a text role and pair it with regular or semibold. Strong emphasis does not introduce another size.

## Corner radius

Choose by surface role: control, inner container, or floating overlay. Pills use the fully rounded token.

## Icon size

Use the base or compact glyph size. Compact icons also need the optically tuned glyph where available.

## Stroke

Use one standard boundary stroke. Preserve thicker accessibility and semantic indicators.

## Color roles

Choose a property and purpose. Component-specific color keys and full theme palettes remain in Colors.

## Elevation

Use the shared surface-shadow scale. High-contrast and shadow settings can suppress these default shadows.

## Motion

Duration and easing tokens are reusable parameters. Recipes keep their geometry and compose those parameters for a purpose; existing component tuning remains intact. Choose the relationship first, then reuse its recipe.

## Scoped layout tokens

Explicitly registered layout decisions retain their workbench scope; ordinary component dimensions are not tokens.

## Deprecated aliases

For existing code only. Prefer the replacement from the shared ramp.
