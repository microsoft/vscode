# Mission Control security and contract requirements

Reviewed on 2026-10-04 against the current implementation, including desktop product activation and the `node/missionControl/` integration. This is a requirement-to-code map, not a security certification or an assertion about every deployed client.

The baseline is the user-local Mission Control, reliable Web PubSub, and portable credential-sealing contracts, with the explicitly agreed compatibility deferrals called out below. Requirements for stronger isolation are recorded separately rather than silently claimed or made prerequisites for the agreed scope. [Check-in readiness](./MISSION_CONTROL_PRODUCTION_GAPS.md) distinguishes implementation cleanup, release evidence, and deferred work.

## Reading the statuses

| Status | Meaning |
| --- | --- |
| Implemented | The specified, bounded behavior exists in this branch. Linked tests establish regression coverage, not universal deployment compatibility. |
| Partial | A named part exists, but the full requirement is not satisfied. The limitation is part of the supported security boundary. |
| Deferred | The stronger guarantee is intentionally outside the agreed increment. It must not be described as implemented. |
| Unverified | Code or packaging support exists, but the required deployment or release evidence is missing. |
| Out of scope | The requirement belongs to a different compute/product variant; this branch must not implicitly enable it. |

Source links identify enforcement or ownership. Test links identify the concrete scenarios to inspect. A successful WPS join or publish acknowledgement is not proof of AHP authentication, provider acceptance, or completed agent work.

## 5. Explicitly absent stronger guarantees

The following must not be inferred from the implemented rows:

- Mandatory handshake binding or anti-replay protection for unbound sealed credentials (S16).
- Client/generation/session credential sponsorship, driver handoff and revocation of shared provider credentials (S18).
- OS/process containment or atomic filesystem isolation; native tool approval is not a sandbox (S23).
- General redaction/zeroization/revocation guarantees for the entire native authentication, provider, logging and export stack (S24).
- Local reimplementation of MC-owned remote-control policy, configurable provider/repository/session limits, or lane-opening rate limits against a compromised signer (S13/S26).
- Conversation E2EE or service-side privacy/retention certification (S29).
- Durable AHP mirror epochs, full initial-history reconciliation, response-part identity continuity, or durable create/send idempotency (S28/S30).

Mandatory binding, shared credential architecture redesign, OS containment, response-part continuity and durable AHP restart work are accepted deferrals for the agreed increment. Broader policy/limit changes and managed compute remain outside the parity scope. The build/product gates and code cleanup are now implemented; missing release/privacy/deployment evidence is **not** converted into completed work by those deferrals. See [remaining work and exact help needed](./MISSION_CONTROL_PRODUCTION_GAPS.md).

## Evidence boundary

The 2026-10-04 two-Code-OSS exercise used separate user-data/shared-storage/SDK homes and native utility processes. Native socket listing proved the fresh test sessions absent from the viewer's ambient host. Discovery and remote turns then used the real MC/Azure WPS endpoint and the owner’s native host. The initial connection remained uninterrupted for 14 minutes 37 seconds before deliberate socket closure; it automatically recovered in about 3.4 seconds with the same client ID, and subsequent remote turns succeeded. Native host restart preserved environment/session identities. Live root-config separation and stable machine naming were verified after hardening.

One viewer application later exited without a recorded cause; the run does not diagnose the Copilot application's reported random disconnections. The URI-stack merge was covered by 2,510 Node and 1,578 Electron/browser tests, types, lint and layering, followed by [green cross-platform Code OSS CI](https://github.com/microsoft/vscode/actions/runs/37240718187), CodeQL and ancillary workflows on `5092cc38c51`. The live two-instance exercise was not rerun after that merge. No temporary protocol downgrade remains.
