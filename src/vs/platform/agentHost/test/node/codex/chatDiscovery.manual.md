# Live external Codex discovery

Use a development Agents Window and the ChatGPT/Codex desktop app that share a Codex home. This checks the cross-process filesystem and UI path in addition to [codexChatDiscovery.test.ts](codexChatDiscovery.test.ts), the Agent Service publication tests, and the local Sessions provider tests.

1. Enable `chat.agentHost.codexAgent.enabled` and choose an external-session visibility mode that includes today. Start with Codex inactive in the host. Listing sessions must not download the SDK or retain a Codex app-server connection; previously cataloged rows can still appear. The existing one-off startup account probe is independent of discovery.
2. Explicitly create/select a Codex session or open a known Codex session in VS Code, completing SDK setup if necessary. Keep the Agents Window open. This activates continuous discovery for this host lifetime.
3. In ChatGPT, create a local Codex conversation and send its first message. Once persisted, its row should appear in VS Code within roughly five seconds plus catalog reconciliation time. A never-persisted draft is not a stored conversation.
4. Rename that conversation in ChatGPT without sending another turn. Its existing VS Code row should update. Send another message in ChatGPT and verify recency and ordering update, including during a long streaming response. In the Agent Host log, discovery must not run once per token; scans are separated by at least five seconds and unchanged rows produce no discovery publication.
5. Open the external conversation in VS Code, then leave it selected. Send another message in ChatGPT. The new request and persisted assistant output should appear without reselecting the session or reloading the window; switch away and back to confirm it remains current. Leave an unsent draft in VS Code and verify it survives. Title and recency should still update; a title explicitly set in VS Code remains authoritative. This is a passive read and must not produce an active-writer error. Simultaneous writes from VS Code while ChatGPT owns the native writer remain subject to Codex's writer lock.
6. Create a VS Code Codex session with an additional chat. Its internal thread backing must not appear as a second external session. Verify that external grouping reads the existing `ISession.isExternal` projection and that the visibility setting can hide/reveal external rows normally.
7. Restart only Agent Host. The list should reconcile automatically without reloading the window. A fresh host remains inactive until an explicit Codex creation/restore; after activation, new external changes resume appearing. Also terminate only the Codex app-server and verify discovery reconnects and resumes.
8. Repeat using `chat.agentHost.codexAgent.codexHome` pointed at a disposable custom home, with the external client configured for that same home. Exercise first creation when the `sessions` directory is absent and creation under a new dated directory. With both native clients stopped, rename/recreate that disposable directory, then resume them. Do not rename or remove a real user's Codex storage. Watches should recover; the one-minute safety refresh also covers missed filesystem events.

Automated native validation can use two app-server 0.153 processes sharing an isolated home and a local mock model endpoint: create a persisted thread and rename it through one process, then verify `thread/list` with `useStateDbOnly: true` from the other for both `legacy` and `paginated` histories. After the first turn, materialize and observe the thread through the real Codex provider, send a second turn from the writer, and assert that the passive history event contains both turns. Neither `thread/resume` nor provider storage parsing is needed for these refreshes. The native history API may report an unfinished external turn as interrupted and exposes assistant text only when the native writer persists it.
