# Mission Control security and contract requirements

Desktop sharing is an explicit machine-filesystem access opt-in: authenticated owner clients can read and modify files beneath `/` on macOS/Linux and available drive-letter roots on Windows, plus explicitly shared local project roots. Home is the browsing default, not an access boundary. This includes sensitive files accessible to the host OS user; it does not elevate the process, waive OS permissions, or change non-filesystem content authorization. The project catalogue remains separate from the granted roots.

Requirement sources, VS Code enforcement and verification. See [remaining gaps](https://github.com/microsoft/vscode/blob/roblou%2Fagents%2Ftypescript-vscode-agent-host-prototype/src/vs/platform/agentHost/node/missionControl/MISSION_CONTROL_PRODUCTION_GAPS.md) and [operation and configuration](https://github.com/microsoft/vscode/blob/roblou%2Fagents%2Ftypescript-vscode-agent-host-prototype/src/vs/platform/agentHost/node/missionControl/MISSION_CONTROL.md).

## 1. Identity and credential authority

**User-host credential authority:** [Mission Control ingress](./missionControlHost.ts) enables scoped client credentials without desktop delegation or shared-token fallback for new turns, queued messages and covered native GitHub operations. Same-owner steering keeps the running turn's credential, matching Copilot Host's implementation; this is not complete permission isolation between same-owner devices. The registration/control-plane credential remains separate (S05); explicit local continuation is an owner-validated local operation, not a remote fallback. Model advertisements intentionally expose only Copilot model lists for client interoperability. Protected execution additionally requires `supportsScopedCredentials: true` and the provider's required credentials from the host-owned source; native Copilot is the supported implementation, and other providers fail closed. S03 has **high implementation priority** with **conditional/medium exploit risk** because same GitHub ownership does not imply equivalent scopes or application restrictions. See [implementation, boundaries and verification](./MISSION_CONTROL.md#scoped-credential-boundaries-and-verification). The documented upstream MCP-App current-session-token behavior and resource-keyed OAuth completion correlation are accepted deferrals outside this scoped execution guarantee.
