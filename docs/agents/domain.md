# Domain docs

This repository uses a single-context layout: `GLOSSARY.md` at the root and architecture decision records in `docs/adr/`.

## Before exploring

Read the root `GLOSSARY.md` and any ADRs relevant to the area you are changing. Continue using `.github/copilot-instructions.md` for project architecture, coding guidelines, and validation.

If the glossary or ADRs do not exist, proceed silently. The domain-modeling skill creates them when terminology or decisions are resolved; setup does not need empty placeholders.

## Vocabulary and decisions

Use the glossary's terms in issue titles, proposals, hypotheses, and tests. If a concept is missing, check the codebase's terminology first and note any real gap for domain modeling.

When a proposal conflicts with an existing ADR, identify the ADR and explain why the decision should be reconsidered.
